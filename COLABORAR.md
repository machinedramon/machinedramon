# Como me ajudar no GitHub

## Por que estou pedindo

Estou organizando meu GitHub pessoal ([machinedramon](https://github.com/machinedramon)) e quero que ele mostre o trabalho que a gente realmente faz junto. Você me ajuda simplesmente trabalhando comigo do jeito certo no GitHub: revisando, pareando e registrando coautoria.

Achievements são selos que o GitHub coloca no perfil quando certas coisas acontecem: um PR aceito, um commit feito a quatro mãos, uma resposta útil numa discussão. Eles só têm valor quando refletem trabalho real, então tudo aqui é sobre colaboração de verdade, não sobre "dar like" combinado.

## Os selos e onde você entra

Três selos dependem de outra pessoa; os demais eu consigo sozinho. Os níveis vêm de guias da comunidade, porque o GitHub não publica uma tabela oficial.

| Selo | O que conta | Níveis | Como você pode ajudar |
| --- | --- | --- | --- |
| Pair Extraordinaire | Commits com coautoria em PRs aceitos | 1 → 10 → 24 → 48 | Quando parearmos, o commit leva a linha `Co-authored-by` de quem participou |
| Galaxy Brain | Respostas marcadas como aceitas no GitHub Discussions | 2 → 8 → 16 → 32 | Quando tiver uma dúvida real sobre um projeto meu, pergunte no Discussions em vez do chat |
| Starstruck | Estrelas num repositório | 16 → 128 → 512 → 4096 | Se você usar ou achar útil um projeto meu, dê estrela e indique para quem também usaria |
| Pull Shark | PRs aceitos | 2 → 16 → 128 → 1024 | Revise meus PRs quando eu pedir; o PR é meu, a revisão dá credibilidade |
| Quickdraw | Issue ou PR fechado minutos depois de aberto | único | Não precisa de ajuda |
| YOLO | Merge de PR sem revisão | único | Não precisa de ajuda |
| Public Sponsor | Patrocinar alguém no GitHub Sponsors | único | Não precisa de ajuda |

Fontes: [github-achievements-guide](https://github.com/kavicastelo/github-achievements-guide), [github-profile-achievements](https://github.com/opencodeera/github-profile-achievements).

## Como fazer na prática

1. **Coautoria ao parear.** Quem fizer o commit termina a mensagem com uma linha em branco e a linha de coautoria. O e-mail precisa ser um dos cadastrados na conta da pessoa (ou o noreply dela, em github.com/settings/emails):

   ```
   feat: corrige colisão do player

   Co-authored-by: Diego Ferreira <diaugustdev@gmail.com>
   ```

   Só conta depois que o PR é aceito (merged), e vale para os dois lados: se eu parear no seu projeto, coloco você como coautor.
2. **Revisão de PR.** Quando eu marcar você como reviewer, comente o que achar e aprove só se estiver bom. Comentário técnico vale mais que um "LGTM".
3. **Dúvidas no Discussions.** Se a dúvida for sobre um projeto meu, abra em *Discussions → Q&A* do repositório. Quando a resposta resolver, clique em *Mark as answer*. Isso ajuda quem tiver a mesma dúvida depois.
4. **Estrelas.** Só se você realmente usar ou acompanhar o projeto. Se usar, contar para alguém que também usaria ajuda mais que a estrela.

## O que não fazer

O GitHub proíbe interações combinadas para inflar perfil e pode remover estrelas ou suspender contas, a sua e a minha. Além disso, quem é do meio reconhece na hora.

- Troca de estrelas ("eu dou no seu, você dá no meu")
- Coautoria em commit de quem não participou do código
- PRs vazios ou de uma linha só para contar
- Perguntas e respostas combinadas no Discussions
